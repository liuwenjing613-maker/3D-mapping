# 逐对象离线修复

当前入口是 `run_case.py --config case.json`。旧 `run_repairs.py` 及双椅专用脚本保持冻结，仅用于复现旧对照；新增入口复用其投影、票据归约和原后处理。

## 明确改动

1. `original_control`：原始二维 mask、原关联、所有历史票和最终地图均不变。它是无操作对照，不做 SAM 推理。
2. `original_reassociate`：种子直接从原始 CropFormer mask 提取，每个对象的二值像素逐项完全相同；通过原有可见表面 Dice 一对一关联重新确定身份。之后仍用 SAM2 双向传播，不意味着所有历史帧都保留原二维 mask。
3. `new_mask_reassociate`：使用人工已选的完整可见物体 mask，在原始 RGB 坐标下传播并重新关联。
4. 每个对象分别判断可见锚点、覆盖、空间范围、其他旧家族重叠和其他种子重叠。数字阈值沿用旧策略。另一个追踪对象的可见种子也作为保护对象，使用已有 20 点/10% 阈值。
5. 所有选中对象可靠且**该张旧观察**在联合空间范围内、联合前景通过其他种子保护时，整张撤回。否则仅撤回可靠新前景覆盖的原家族像素，其余原像素重新投影保留。仅部分解释旧观察时，不能把整张观察删除。
6. 允许修改范围仍是被撤回贡献的表面与可靠新前景表面的并集；不包含仅因保留而存在的未知残余。全局计算后处理候选，提交时用原有严格局部函数固定外部标签。

同帧、同点、同实例最多一票。另一个保留像素/观察仍支持相同票时，这一票保留。每个案例验证完整 400 帧重算、增量更新、准确回滚、全部外部原始证据和票据，以及最终外部标签零改动。

## 使用

```bash
cd /home/chenkejun/CVPR/experiments/pilot10_repair_20261007/objectwise_repair_20261007
/data/chenkejun/beauty/ovo_paper_original_20260915/env/bin/python run_case.py \
  --config case_room2_original_seed.json \
  --evaluation-config evaluation_room2.json
```

三个随附 case 配置分别是原关联对照、原 mask 重新关联、原先选择的 SAM2 局部候选。场景、人工记录 UID、种子帧、追踪对象、原 mask ID、旧家族、输出目录和追踪参数来自配置，不再写死在修复入口中。对象按 track_id 升序排列。支持当前冻结 Replica 场景基线与对应人工种子清单；不是任意数据集的适配器。

GT target IDs、固定表面评价缓存和对比地图路径只放在 `evaluation_room2.json`。修复完成、预测及来源冻结后才启动单独评价进程。主评价仍为原 v3 代码、协议和参数；固定表面函数及对应缓存不改。协议仍为 pending/debug，正式结果前还需独立校准和冻结。

新案例删除 `tracking.reuse_dir` 和 `tracking.source_code` 即重新推理。两个方向使用各自独立、只在种子初始化的状态，处理完整原始序列；不会切换为在线或只向前。复用轨迹前核对所有原始帧校验和、种子像素、方向、代码及权重。原 mask 改变了种子像素，必须独立推理。

代码在 `/home/chenkejun/CVPR`；结果在 `/data/chenkejun/CVPR`。每个配置应使用独立输出目录。完成后再次运行只校验冻结输入和结果，不重复写图。来源或代码改变时拒绝复用旧完成记录。

## 尚未改变的限制

- 旧家族 ID 由人工在配置中指定，本轮未实现跨历史其他 ID 的自动检索。
- 锚点还是初始种子表面；背面不可见或追踪漂移仍可能导致拒绝，未加入新种子、多段记忆重启。
- “全部对象可靠”沿用锚点与空间检查，并不能保证新 mask 完整解释旧观察；整张替换仍可能新增未分配点。部分替换保留未知，不能保证全图灰点减少。
- 一对一 Dice 是现有 GT 无关启发式，不是已验证的全场景最优关联。
- 多案例当前分别从同一冻结 baseline 开始。重叠案例不能直接把各自最终地图叠加；本轮尚未实现串行累计提交。
- 没有更改确认阈值、权重、TSDF几何，没有加入自动ROI、VLM、在线状态。

方法正确性通过不代表修复指标达到目标。先跑一个场景 10–15 个代表案例及无需修复的对照，报告目标覆盖/纯度/IoU、旧身份残留、灰点、非目标损伤与计算开销。
