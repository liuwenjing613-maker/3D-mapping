## 实际采用的策略

- stride=5；第50/100/200/300个处理帧截止raw245/495/995/1495。候选、几何、追踪和历史改票只使用已到达前缀。
- 第50帧暂停并修复提交；第100帧按原A13/B12种子分别修复，两分支独立续建。
- A在200/300帧从1–200/1–300选候选；B从101–200/201–300选候选。两组均保留种子并在全部已到达原始RGB中双向稠密追踪。
- 最先排除整帧或任何局部crop触边mask，沿用原双95%规则及现有语义豁免；窗户/柜子的SAM来源规则保留。pr95_90目录仅为历史比较，不是本次修复策略。
- 保留partial、核心历史重关联、E1扩展/历史改票、严格一票及逐阶段后处理。省去旧whole对照审计计算。
- 主建图在修复时暂停；像素历史、票据、身份索引和持久ID提交后继续。表面变化后重新投影历史像素，不复用旧表面索引。
- 只复用同前缀、同种子、同模型和同代码等输入完全相同的追踪结果，各分支独立执行Gate。没有降低追踪频率。
- 两组均停在300帧修复提交后，没有处理第301帧。

## 代码入口

核心目录：../online_room0_repair50_to100_20261022/。其中prefix100、prefix100_new50、tracking100和repair100保存100帧分支流程；continuation300保存200/300续建。

- continuation300/map_commit_controller.py：A/B主建图和提交调度，止于300帧。
- continuation300/selection_run.py：候选与追踪入口，运行前明确指定CVPR_CHECKPOINT=200或300、CVPR_TRACK_GROUP=A或B，默认200/A。
- continuation300/repair_controller.py、audit_controller.py：等待前序完成后执行修复和最终核验。
- continuation300/visuals/：200/300四图导出、联合实例配色、计时和发布展示。
- ../online_room0_prefix20_20261021、prefix50、prefix80相关目录保存前缀探索；online_full_frame_edge为早期只排整帧边界试验，最终采用online_all_edge。
- source_manifest.json保存每份源码的原路径、符号链接解析目标、字节数和SHA256。归档链接已物化，避免checkout丢失文件。
- evidence/与evidence_manifest.json保存四个检查点的完成记录、提交/因果核验、计时和八份PLY字段核验。大型数据不进入Git。
