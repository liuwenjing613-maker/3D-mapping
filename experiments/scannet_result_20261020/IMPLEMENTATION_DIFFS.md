# ScanNet 实现差异与相同部分

比较对象为父提交 `1103d8196a980874ef743f572d3b4c0748a4fdab` 的冻结 auto-v3-swap 流程与其继承的 E1。`source_inventory.json`使用完整字节哈希识别继承源码；不能只凭文件名或功能相似声称实现一致。所有新增或有差异的实际运行文件均保存在 `code/`，能对应源文件的统一差异保存在 `diffs/`。

## 相同部分

- 原冻结 E1 数值核、严格一票与歧义弃权、历史重关联、自适应可信范围扩展、门控及回滚机制保持不变。归档没有修改 `instance_repair/frozen_e1_20261012`。
- 自动种子仍使用 auto-v3-swap 的筛选顺序：背景、共同可见IoU去重、完整支持包含、覆盖充分、第五项筛选；窗户/柜子仅豁免第五项。阈值不因ScanNet调整。
- partial 使用既有 partial 撤票规则，和E1共用种子、追踪、ID、可信范围和门控。它不是一套重新选种的算法。
- 评分使用 main 锁定的 R2 源码；评价仍是开发基准，`frozen=false`。

## 必须归档的差异

| 范围 | ScanNet 实际适配 | 对可比性的影响 |
|---|---|---|
| 帧与相机输入 | 640×480，两个场景分别238/339个现有步长10帧，原始帧号保留；RGB按颜色/深度内参映射到深度网格 | 没有补造中间帧；不能按Replica400帧解释 |
| 深度 | 输入适配器使用既定0<depth<4m，投影仍为pixel_stride=2、最大距离0.015m | 数值投影核不变；无有效投影种子按用户规则跳过 |
| CropFormer控制验证 | 控制图使用历史原始RGB推理，再做标定的最近邻标签采样 | 用于核对与历史缓存的一致性，不改模型阈值 |
| 严格无修复基线 | 使用当前E1正向投影和严格一票，不使用历史反向投票代替 | 只有新baseline/E1/partial组成固定几何的修复对比 |
| 零有效投影 | scene0011跳过G076/M0107；scene0608按相同规则跳过G091/M0176、G127/M0241、G212/M0395 | 原始自动选择保留；E1/partial执行集合一致 |
| SAM-only来源规则 | scene0608裁剪/噪声过滤后重分组再次调用既有r2规则；裁剪后移除M0138/M0141/M0163的11条CropFormer来源 | 用户已确认；整掩码排除，不改像素、阈值或语义模型；每步证据留痕 |
| 场景例外 | 不推广Replica room0 M0466与room2 G017/G025的人工例外 | ScanNet自动选择及执行跳过单独记录 |
| 评价入口 | ScanNet wrapper导入main锁定R2函数，使用历史已审核的27/34 GT场景配置和固定对应索引 | main默认CLI当前只接受Replica范围，不能声称本次直接走默认CLI或使用350 GT |
| 调度 | 数据/结果路径隔离；可用GPU检查与并发安排；断点恢复 | 仅运行管理；完成后检查全量回放、delta一致、精确回滚和作用域外不变 |

两场景的输入、规则、所用源码哈希、执行种子与审计状态以对应场景的归档为准。仅完成第一场景的提交不会把第二场景预告当作已完成结果。部分继承审计字段名含`all_400_frames`，实际断言使用238/339帧；不要按字段名称推断帧数。

## 如何恢复运行目录

遍历`source_inventory.json`的`records`，将仓库中`repository_path`指向的文件复制到独立运行目录的`runtime_relative_path`，每次验证`sha256`。`unchanged_inherited`项来自父版本现有文件，其余来自本归档`code/`。这能恢复已归档源码字节；原始ScanNet数据、TSDF、模型与追踪缓存仍需按输入来源锁准备。不要将历史绝对输出路径直接用于重新计算。
