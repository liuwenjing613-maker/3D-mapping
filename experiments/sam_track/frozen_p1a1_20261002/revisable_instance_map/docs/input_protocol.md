# 无修复空图建图：首个输入协议

## 本轮固定的开发输入

- 场景：Replica `room0`。
- 顺序：原始帧号 `0, 5, 10, ..., 1995`，共 400 帧；每个入图帧同时有 RGB、深度、位姿和预计算的二维实例 mask。
- 选择理由：与现有 room0 控制实验的 400 帧、步长 5 保持一致，且已存在同帧 mask 缓存。OVI-MAP 的论文对齐运行是 200 帧、步长 10，属于另一输入协议，结果不能直接混列。
- 具体路径和相机参数见 `configs/replica_room0_stride5.json`；完整性检查见数据盘的 `input_audit_room0_stride5.json`。

## 解码约定

| 输入 | 约定 |
|---|---|
| RGB | `frame{原始帧号:06d}.jpg`，1200×680，RGB |
| 深度 | `depth{原始帧号:06d}.png`，16-bit 单通道；米 = 原始值 / 6553.5；无效深度不得投影 |
| 位姿 | `traj.txt` 第 `原始帧号` 行，行优先排列的 4×4 camera-to-world 矩阵；首版不将第一帧重置为单位阵 |
| 内参 | `fx=fy=600`，`cx=599.5`，`cy=339.5`，与 1200×680 图像对应 |
| mask | `frame{原始帧号:06d}.png`，8-bit 单通道；0 为背景，正整数是**该帧内部**的实例提案编号，不能跨帧当成持久 ID |

现有 mask 缓存的 `frames.jsonl` 逐帧记录 RGB 和 mask 的 SHA-256。缓存属于本项目的只读输入；不在无修复阶段重新运行分割模型，也不使用 GT mask。

## 在线和评估边界

在处理帧 `t` 时，建图只读取本协议中编号不大于 `t` 的观测。无修复阶段保留原 mask，不调用即时或历史修订器。GT 仅由独立评估器读取；首版最终输出按已经冻结的 Replica-CA-v1 协议评估，逐帧快照只作在线诊断。

目前源 Replica 数据和 mask 缓存仍在既有路径，保持只读；所有本项目新代码和结果只写入同名 `CVPR/revisable_instance_map` 目录。此步骤没有移动或复制既有数据。
