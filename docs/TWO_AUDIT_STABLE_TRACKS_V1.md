# Two-audit 第二环节：稳定原始 Mask 观测簇 v1

## 范围与已确认设计

分支 `two-audit`。本环节读取第一环节的原始观测缓存，以相同 TSDF 表面索引空间关联原始 Mask；离线验证优先，offline 与 online-v2 共用同一套实现。当前阶段输出稳定性证据，不读取地图实例 ID、不使用 GT，不产生异常 ROI、筛选保护或修复决策，不修改原图或冻结修复内核。

用户确认的参数固定为：

| 参数 | v1 |
|---|---:|
| 双方在共同可见区域内的支持点下限 | 各 25 |
| 共同可见 IoU 下限 | 0.55 |
| 稳定簇最少有效观测 | 3 个不同帧 |
| 稳定簇最少视角组 | 2 |
| 新视角组的位置/方向差异 | 0.1 m 或光轴方向 10° |

没有依据本次结果自动调参。语义、当前实例 ID、图像边缘等均不参与关联门槛；边缘标记仅保留给审阅。

## 共同可见比较

设原始 Mask 在当前固定表面的支持为 S_a、S_b，对应帧的有效可见集合为 V_a、V_b（包含背景表面）。计算：

- common_a = |S_a ∩ V_b|
- common_b = |S_b ∩ V_a|
- intersection = |S_a ∩ S_b|
- union = common_a + common_b − intersection
- IoU_cv = intersection / union，仅当 common_a、common_b 均至少 25 时有效。

共同支持不足记录为 INSUFFICIENT_COMMON_SUPPORT，IoU 为 null，不能解释为两个观测属于不同实例。双方共同区域占各自完整支持的比例一并输出，便于审阅局部可见造成的高 IoU。

候选查找采用精确表面点索引的倒排表。只有支持点存在交集的既有簇才需要计算 IoU；零交集不可能达到正 IoU 阈值。此剪枝不使用地图 ID、不做包围盒近似。证据文件包含所有实际计算的比较，不包含被零交集条件直接排除的组合。

## 固定代表与同帧分配

按原始帧顺序处理。每个簇的代表是首次建立该簇的有效观测；代表支持复制后设为只读，后续不更新、不把成员并集替换为代表。每个新成员必须直接匹配这个代表，避免 A 匹配 B、B 匹配 C 导致无约束串联。

同一帧先完成所有比较，再统一分配；该帧新建的代表在下一帧才参与关联：

1. 总支持不足 25 的观测：DEFERRED_INSUFFICIENT_SUPPORT，保留原始记录，不建簇。
2. 满足条件的代表为零：NEW_TRACK，建立临时簇。若已有比较只显示共同可见不足，则明确保留“无法判断”原因；新临时簇不代表独立实例判定。
3. 恰好一个满足条件的代表：提出加入申请。
4. 多个满足条件的代表：DEFERRED_AMBIGUOUS，进入待定池，不加入任何簇，也不作为新代表。
5. 同帧多个观测申请同一簇：全部 DEFERRED_SAME_FRAME_CONFLICT，不按处理先后抢占；只有唯一申请者可加入。

待定观测在本版中不进行二次分配、不计入稳定性，原始身份、匹配列表和原因全部保留。相同局部区域因早期可见性不足建立多个临时簇时，后续可能出现大量多簇匹配歧义；这需要后续审查，不能静默合并或选最高分。

## 视角组与稳定性

相机位置使用 camera-to-world 平移，观察方向使用归一化光轴（旋转矩阵第三列）。相机绕光轴滚转不会独立产生新的观察方向。

每个视角组使用首次成员的固定相机姿态。新观测与某组代表的位置差小于 0.1 m 且光轴差小于 10°，则进入首个兼容组；只有与所有现有组代表均满足“位置至少 0.1 m 或光轴至少 10°”时才新建视角组。小量数值容差仅处理恰好落在边界的浮点误差。

簇内至少 3 个不同帧、至少 2 个视角组才标为 STABLE，记录首次达到条件的原始帧号。它仅表示固定代表得到跨视角观测支持，不能证明独立物体身份、分割正确性或地图需要修复。

## 实现与命令

- `instance_repair/two_audit_matching.py`：集合比较、固定代表、视角组、同帧冲突和歧义处理。
- `instance_repair/two_audit_tracks.py`：缓存适配、构建、完整证据账本、输出验收。
- `instance_repair/tests/test_two_audit_tracks.py`：22 项测试，包含随机集合参考计算、歧义、固定代表、防串联、视角边界、因果前缀及端到端文件校验。

在服务器工作区运行：

```bash
cd /home/chenkejun/CVPR/worktrees/two-audit
PYTHONDONTWRITEBYTECODE=1 OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
/data/chenkejun/beauty/ovo_paper_original_20260915/env/bin/python -B \
-m instance_repair.two_audit_tracks build --cache CACHE_DIRECTORY --output NEW_OUTPUT_DIRECTORY

PYTHONDONTWRITEBYTECODE=1 OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
/data/chenkejun/beauty/ovo_paper_original_20260915/env/bin/python -B \
-m instance_repair.two_audit_tracks verify --tracks OUTPUT_DIRECTORY --verify-inputs
```

输出路径不得位于输入缓存或原地图目录内，已存在路径拒绝覆盖。不同检查点必须使用各自的缓存/geometry_id，禁止复用上一检查点的表面点编号。online-v2 这里只做前缀缓存的接口兼容性检查，尚未接入实际检查点修复流水线。

## 输出与溯源

| 文件 | 内容 |
|---|---|
| request.json / manifest.json | 缓存、几何、帧前缀、参数、代码哈希与输出哈希 |
| input_validation.json | 输入缓存和原始数据/几何来源校验 |
| tracks.json / stable_tracks.json | 全部临时/稳定簇及稳定子集、固定代表和成员证据 |
| observation_decisions.jsonl | 每条原始观测唯一的归属或待定原因 |
| pending_observations.jsonl | 全部待定观测，含小支持和歧义 |
| pair_evidence.jsonl.gz | 每次实际比较的集合计数、IoU、共同可见比例与来源 |
| track_summary.csv | 便于排序查看的逐簇统计 |
| review_samples.json | 长稳定簇、小支持稳定簇、同视角重复簇及歧义样例的来源索引 |

构建前校验原始数据和缓存；完成前重新核对输入缓存元数据、全部支持包及本环节实现文件的哈希。所有原始观测必须恰好出现在决策账本一次，归属数量与待定数量闭合。验收重放视角分组和稳定起点，核对固定代表、同帧唯一、所有比较分类、归属账本及待定账本的一致性。另对真实场景抽样使用独立 Python 集合重算，结果保存在运行目录 `diagnostic_checks.json`。

## 补充验收与已观察到的限制

两场景各按 MATCH / BELOW_IOU / INSUFFICIENT_COMMON_SUPPORT 抽取 120 对，共 720 对，用独立 Python 集合重算共同支持、交集、并集和分类，全部一致。另各抽取 120 条多簇歧义，检查其中得分最高的两个代表：5ee 的 79 对、825 的 80 对代表之间共同可见支持不足，其余分别 41 / 40 对低于 IoU 门槛。该结果只解释本次抽样中的关联歧义，尚不能判断它们属于同一物体还是不同物体。

两场景稳定簇的成员数中位数均为 5，视角组数中位数均为 3；各有 130 / 115 个稳定簇的所有成员均接触图像边界。已测得的全部 MATCH 比较（含最后被暂缓的比较）中，双方共同支持占完整支持比例的较小值中位数为 13.75% / 15.00%。这些量已保存供审阅，当前没有追加边缘过滤或相对覆盖率门槛。

online-v2 的 5ee 场景 100 帧 B 缓存使用同一构建器与生产参数，通过完整输入来源复验与输出校验：2648 条原始观测、55 个稳定簇、423 个临时簇、662 条小支持待定、531 条多簇歧义待定，构建 9.83 s。这里只验证已存在因果前缀缓存的适配，不声称完整 online-v2 检查点调度或修复闭环已接入。

本轮未完成人工图像质量标注；`review_samples.json` 保存的样例是审阅入口，不是人工正确率结论。待后续环节确认后，再对固定地图上的 ID 对应、共同可见分离和现有三状态 ROI 覆盖进行只读检查。
