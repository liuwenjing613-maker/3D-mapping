它要求可信范围与原 E1 完全一致，且每个场景的 400 份事务及 5 份地图/证据/范围 NPZ 的所有字段、类型、形状、数组完全一致，最后写出 `replay_verification.json`。
已存在输出不会覆盖；失败时保留日志和现场。只在新目录重试。

## 冻结规则

1. **可信核心。** 每个种子选择从 10 到 1 的最大腐蚀半径，使投影唯一点数达到 `max(20, ceil(0.2 × 种子投影点数))`。没有满足条件的安全内部时不以半径 0 强行扩张；保留原核心。同 ID 种子联合，不同 ID 核心相交处标为歧义。room0 Mask35 按用户最后确认视作桌子，不作为书本种子。
2. **可信范围。** 候选来自接受 Mask 腐蚀 1 像素后的固定前向投影（步长 2，最近 TSDF 距离 0.015 m）。用 TSDF 点反投影检查深度可见性（容差 0.02 m），要求至少 3 帧支持、至少 2 个相距 0.05 m 的代表视角支持、可见帧中支持比例至少 0.8。只有合格点能沿 0.02 m 邻接从核心扩展，不跨越弱证据桥。同 ID 别名逐个腐蚀再取并集，每帧只计一次；不同 ID 同时认领处歧义，去掉歧义桥后重新检查连通性。没有把所有追踪 Mask 直接取并集。
3. **历史修订。** 仅对仍保留的原始采样像素观察，在唯一可信归属区域且本帧深度可见时局部改归属；不受旧家族 ID 限制，不全局替换旧 ID。被撤换的、不可见的、范围外或无法确定归属的观察保持原规则。
4. **新观察和投票。** E1 保留原有已接受新 Mask 票，不使用 E2 的局部新票剔除。修改原始观察后重建整帧：同点同 ID 去重；同点不同 ID 本帧全部弃权。同 ID 的一个 Mask 撤销后，其他有效 Mask 的共享支持仍保留。确认门槛保持至少 2 票且第一身份比例至少 0.67。
5. **提交范围。** 后处理使用锁定的 holes-geodesic 参数；最终只提交相对对照累计票发生变化的点。范围外标签与证据保持逐位一致，检查增量与全量 400 帧归约一致以及撤销后精确恢复。

## 源码与输入追溯

`instance_repair/frozen_e1_20261012` 保存两个场景已验证算法、原始参数、来源哈希、运行环境版本及其历史依赖源码快照。
旧模块名通过锁定加载器解析到 main 内的快照，避免依赖服务器实验目录里之后可能被编辑的源码。归档依赖保留原始内容；独立 E1 入口仅移除了 E2 分支，算法结果通过完整重放验证。
`source_lock.json` 锁定运行源码及注册信息；`original_source_provenance.json` 记录整理前的来源；每场景 `reference.json` 锁定原 E1 数组与对应 R2 指标。外部输入由原有哈希校验和基线重建断言检查。
快照中的历史路径用于读取服务器现有数据；快照不应直接作为新开发入口。后续算法变更应使用新版本和新输出目录，不原地覆盖此冻结目录。源码锁用于可重复性校验，不是权限或防恶意篡改机制。
