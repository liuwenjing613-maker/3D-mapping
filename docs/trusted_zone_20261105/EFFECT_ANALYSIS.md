# 可信区域策略：完整在线与同版 DBSCAN 效果分析

## 结论

本次干预提高了检测/匹配计数指标，但没有全面改善实例地图。与 PPT 最新 v2-B + DBSCAN 相比，F1 +1.97 pp、AP50 +2.77 pp、AP +1.04 pp、PQ +1.30 pp；匹配实例平均 IoU（SQ）下降 0.42 pp，正确归属覆盖率下降 0.31 pp。原 7 个严重退化没有恢复，同后处理对比出现第 8 个严重案例。应将其保留为有收益也有明显代价的实验分支，不能作为已解决在线修复破坏问题的结论。

## 实验口径与版本

- 8 场景，每场景完整 400 帧；原在线 v2-B 与可信区域 online_B 各一组，再各自使用完全相同的终末 DBSCAN，组成四角对比。
- PPT 最新 DBSCAN 是 history_seeded 最终结果，包含独立共视约束、严格逐帧重投票、最终 B、补灰和历史核心补全；不能用仅 guarded 阶段冒充最新基线。
- 原 v2-B 与候选使用相同最终固定几何、RGB、GT 和对应索引。评价来自 main R2（350 GT，frozen=false），不是另一分支自带的旧评估器。
- 原版 8 场景重跑后 xyz/RGB/instance_id 逐点一致，才处理候选 8 场景。全部完成，四组汇总和逐 GT 复核通过。
- 控制与候选 4 场景并行做 DBSCAN；在线阶段最多 8 场景调度。数值函数和阈值没有为本次结果修改。
- 比较是终末后处理，不将 DBSCAN 输出回写在线流程；本次没有重复新做关闭某一环节的完整因果消融。

## 为什么视觉退化很多，分数却提高

### F1 对过线后的质量下降不敏感

实际源码 unified_eval/metrics.py 采用最大匹配数优先、再最大 IoU 的一对一匹配，门槛严格为 IoU>0.5。F1=2TP/(2TP+FP+FN)。四组比较固定 350 GT。
旧方案 TP244、FP151、FN106，计分预测395；新方案 TP250、FP141、FN100，计分预测391。8 个实际新增匹配抵消 2 个失配，净增6 TP。FP减少10并不等于删除10个错误碎片：其中6来自TP净增加，另外4来自计分预测数量净减少。
对 F1=2TP/(350+Npred) 做两种变更顺序平均的精确对称分解，TP数量贡献 +1.6151 pp，预测数量贡献 +0.3579 pp，加总 +1.9730 pp。这是公式贡献分解，不是算法因果归因。

| 实例 | IoU 旧→新 | F1匹配状态 |
|---|---:|---|
| room0 GT4 书本 | 0.6891 → 0.5353 | TP → TP |
| room0 GT30 百叶窗 | 0.9107 → 0.5094 | TP → TP |
| room0 GT58 百叶窗 | 0.8455 → 0.6173 | TP → TP |
| office0 GT9 沙发 | 0.9498 → 0.7630 | TP → TP |

room0 GT85 书本和 office1 GT18 瓶子原本未过线，进一步变差也不会再减少 TP。实例等权计数不会让损失几千个表面点的大物体承担更大 F1 代价。

### AP50 与 PQ 并非独立的完整性改善证据

本协议使用 uniform confidence，相同置信度整体评估，不靠 UID 排序。AP50 等于 precision × (满足 recall 阈值的101级采样点数量/101)。旧值为(244/395)×70/101=0.4281238250，新值为(250/391)×72/101=0.4558000557；已用正式源码与结果逐项还原。
PQ=RQ×SQ。RQ即该处F1，从65.5034%升到67.4764%；匹配集平均IoU SQ从80.2272%降到79.8107%。PQ增长是计数收益盖过SQ下降。匹配集成员发生变化，因此SQ下降不能单独证明每个共同匹配实例都恶化。

### 表面损伤与变化幅度

正确归属点 1,267,702→1,262,748（−4,954）；错误归属点230,606→235,125（+4,519）；有几何但未分配点63,220→63,655（+435）。几何缺失点56,175不变。room0 GT30百叶窗正确归属少6,499点，office0 GT9沙发少4,916点，这与点云中的明显损伤一致。
109个IoU退化不都是大变化：下降超过0.01的37个，超过0.05的14个，超过0.10的7个；提升超过对应幅度的分别46、19、13个。全部GT的IoU正变化总和4.17867、负变化总和−2.91440，平均只增加0.003612，变化中位数为0。
结构诊断也有混合结果：显著分裂GT总数137→134、显著混并预测101→96，改善整体计数并不消除沙发等新增局部错误。未匹配计分预测中，大小<100参考点的58→51；这只是两组分布变化，不能据此声称同7个碎片均被策略删除。

## 已核验的流程证据及因果边界

1. **office1 GT18瓶子**：早期两个冲突桥接点变成稳定tissue ID9，原162点告警连通域分为76/45/39点，候选排名33/46/51落到top20之外；独立瓶子种子未进入后续。固定图反事实可恢复候选排名，但没有完整关闭策略再重跑的消融，不能宣称全链条因果贡献已精确确定。最终瓶子仍混在ID9；DBSCAN保持瓶子命中53点、预测大小405→409，IoU略降，历史补全没有重建旧独立瓶子身份408。
2. **office0 GT9沙发**：原种子Dice0.550351能关联79，新种子Dice0.493700低于0.5而产生572；300帧修复把一部分表面79→572。其后可信572使18个原拟合79的mask整张弃权，已有分裂被保护。DBSCAN中79/572未进入合并预筛，不能说被共视规则拒绝；历史补全确实使用本轮300的572核心，补256个surface点，却没有消除分裂。
3. **room0 GT30百叶窗**：同一raw1995种子出现multi-partition/no-family跳过；原400帧有有效57修复，新流程该轮没有采用57。但此前历史已不同，不能把全部损失归因于该一次跳过。DBSCAN中57/195重叠不足，未接受合并；GT30只小幅补灰。
4. **room0 GT85/GT4书本**：新流程对应书本候选未入选，不是显式skip；书本混入ID16。room0本次没有任何accepted merge，终末补全未把混合身份拆开。
5. **room0 GT58百叶窗**：后处理主预测命中13780不变，但预测22129→22322，IoU由0.6227降至0.6173。扩大预测不等于更准确。
6. **room0 GT92书本**：旧流程普通补灰后IoU0.058824，历史核心补全后0.550523；新流程0.324042→0.358885。旧605来自300帧，旧区域508点、20核心点保留，拟补432 surface点；新391来自200帧，区域94点、26核心点保留，拟补26点。两个历史身份不能视为同一个ID，也不能仅凭该差异推断某条seed被策略删除。

总体上，可信区参与下一帧关联和后续候选选择，既可能保住正确身份，也可能把早期错误分裂继续固定下来，或压掉需要后续修复的告警。这是现有日志和各阶段输出支持的机制解释；所有上述局部反事实均有范围限制，不替代完整独立因果消融。

## 展示选择与建议

此前PLY重点菜单刻意包含8个严重退化和1个改善案例，不是均匀随机抽样，不能用该菜单估计全数据集退化比例；但正确归属和SQ的下降证明，问题也不是单纯展示偏差。
本分支记录实验，不改变默认策略。后续若继续开发，应分别核查整mask弃权、候选topK变化、低质量新身份被保护、可信区竞争与历史补全收益差异；先设计独立对照，再实现和运行，不能通过针对这些GT临时调参声称普遍改善。
